# Применить cosmos-kit к готовому проекту («примени UI»)

Цель — тот же проект с тем же поведением, но в языке кита. Логику, маршруты, API, имена полей и тексты
интерфейса не меняем; меняем разметку (классы), стили и оформление сообщений.

## 1. Установка (один раз)

`python3 ~/.cosmos-kit/src/tools/cosmos.py init` в корне проекта. Он сам найдёт, где лежит статика, положит туда
кит, запишет `cosmos.json` и поставит хуки. Проверь две строки в `cosmos.json`:
- `kit_url` — адрес, по которому браузер получит файлы кита (`kit/`, `/static/kit/`, `/kit/`). Сервер должен отдавать
  папку `kit_dir` по этому адресу: у статики — само собой; у приложения — добавить отдачу этой папки (как у остальной статики);
- `serve` — команда запуска приложения с `{port}` (для браузерной проверки), `pages` — адреса экранов, например `["/", "/settings"]`.

## 2. Опись

Список экранов/шаблонов (`cosmos.py init` печатает число; HTML внутри кода — поле `embedded`). Для каждого — какие там
элементы. Работаем экран за экраном, после каждого — `python3 kit/tools/check.py <файл>`.

## 3. Голова страницы

- Убрать чужие CSS-фреймворки и шрифты (Bootstrap, Tailwind, Google Fonts) — линтер P5.
- `<html lang="ru" data-theme="dark">`; в `<head>`: `fonts.css` → `tokens.css` → `components.css` кита → свои стили.
- В конце `<body>` — `<script type="module">import { bootSite } from '<kit_url>js/site.js'; const site = bootSite({ page: 'app' });</script>`
  (`page: 'app'` — приложение, `'inner'` — страница сайта, без параметра — главная с героем). Есть свой JS-модуль — импорт туда.
- Сцена: в приложении — `<div class="cosmos-wrap asleep" id="cosmos-wrap">…` (разметка — `starter/app.html`) или без неё.

## 4. Замена элементов

| было | стало |
|---|---|
| боковое меню / сайдбар | `.app` > `.rail` > `.rail-nav` (блок app-shell) |
| верхнее меню сайта | `.topbar` (блок topbar) |
| главная кнопка экрана | `.btn.primary` (одна на экран) |
| прочие кнопки | `.btn`; маленькая — `.btn.small`; с иконкой в строке — `.chip-btn`; только иконка — `.icon-btn` + `aria-label` |
| одно главное поле экрана (поиск, ссылка) | `.field` (разметка — «Поле ввода» в `references/connect.md`) |
| обычные поля, select, textarea | `.in` внутри `<label>` с подписью над полем; группа — `.form-grid` |
| чекбокс вкл/выкл | `.switch` (блок form) |
| выбор из 2–16 вариантов | `.choices` > `.choice[aria-pressed]` |
| карточки, панели, блоки | `.panel` (раздел экрана), `.card.static` (контент), колонки — `.cols`, сетка — `.grid-3` |
| список записей | `.list` > `.item` (блок list) |
| таблица | `.table-wrap` > `table.data`, числа — `.num` |
| вкладки / переключатель | `.tabs` / `.pills` с `data-segmented` (блок tabs) |
| модальное окно | `<dialog class="modal"><div class="modal-box">…` + `data-open`/`data-close` или `openDialog()` |
| `alert()` / всплывашка | `site.toast('ok' | 'err' | '', 'текст')` |
| `confirm()` перед удалением | блок dialog-confirm (только для необратимого; обратимое — сделать и дать «Отменить») |
| бейдж, метка | `.tag`, `.chip` (число — `.chip.mono`) |
| прогресс | `.meter` > `.meter-fill[style="--p:.6"]` |
| пустой список | `.empty` (блок empty) |
| предупреждение в форме | `.notice.err` / `.notice.warn` в потоке, не поверх |
| цифры-итоги | `.kpis` > `.kpi` |

JS, который строит разметку строками (`innerHTML`, шаблоны, `el('div','row')`), — классы меняются и там.
`id`, `name`, `data-*`, обработчики — не трогать.

**Логику не ломать** (браузер сверяет с эталоном «до кита», B9/B10):
- способ подключения скриптов не менять: был `<script src="app.js">` — пусть остаётся; `bootSite` — отдельным
  `<script type="module">` рядом. Не переводить старый скрипт в модуль и не грузить его через `import()` — его
  `DOMContentLoaded`/`onload` тогда не сработает и данные не отрисуются;
- функции, которые зовутся из разметки (`onclick="addBook()"`), должны остаться глобальными;
- `prompt()` для ввода → форма в `<dialog class="modal">` с `.form-grid`; `alert()` → `site.toast()` (site — из `bootSite()`,
  для старого скрипта: `window.site = bootSite(...)`); `confirm()` → блок dialog-confirm.
- Сайдбар → каркас app-shell (`.app` + `.rail`), и тогда никакой `.topbar` (H10).

## 5. Свои стили

Всё, что осталось от старого CSS: цвета → токены (`--ink`, `--ink-2`, `--ink-3`, `--s1…--s4`, `--line-1…3`, `--el-a`),
шрифты → `--font-text|display|mono`, длительности → `--t-fast|base|slow`. Правила, которые переопределяют классы кита
(`.btn { … }`), удалить. Проверка — `python3 kit/tools/check.py` без ошибок S1–S6.

## 6. Сдача

`python3 kit/tools/cosmos.py done` (поднимет приложение по `serve`, снимет каждую страницу из `pages` на 2560, 1920 и 390).
В отчёте — какие экраны переведены и что осталось старым (если осталось).
