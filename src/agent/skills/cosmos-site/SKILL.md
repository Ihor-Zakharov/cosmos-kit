# Интерфейс на cosmos-kit

Работай сам и до конца, без уточняющих вопросов: чего не знаешь — реши разумно и запиши в допущения отчёта.
Работа сдана, только когда `python3 kit/tools/cosmos.py done` напечатал `cosmos-done: OK`.
(`kit/` — папка кита; в проекте она может называться иначе — см. `cosmos.json` → `kit_dir`.)

**10 правил, которые нельзя забыть** (коды — `python3 kit/tools/check.py --rules`; подробно — SKILL.md и `references/lessons.md`):
1. Сдано = строка `cosmos-done: OK` от `python3 kit/tools/cosmos.py done`. Нет строки — работа не сдана и отчёт не пишется.
2. `kit/` не правится (K1) и не читается целиком (`kit/css`, `kit/js`, демо): классы, токены, иконки — `check.py --classes|--tokens|--icons <слово>`.
3. Разметка — из `kit/blocks/` по `INDEX.md`; классы только существующие (H4); иконки `kit/icons/sprite.svg#i-…`, эмодзи нельзя (H6).
4. Своё — в `site.css`/`site.js` только на токенах `var(--…)`: без #hex, своих шрифтов, `@keyframes`, inline `style=`, `!important`, CDN (S1–S6, P5, J3).
5. Одна `.btn.primary` на экран, секцию и диалог (H1, B4); красная `.btn.solid.danger` — только в `<dialog>` подтверждения (H3); без `alert/confirm/prompt` (J1).
6. Текст читается в каждом состоянии (обычный, сделан, активный, наведение, фокус) и палитре: контраст ≥ 3:1; на заливке `--ink` цвет текста `--bg` (S10, B11).
7. Переключатель не двигает раскладку: позиция и высота соседей до и после одинаковы (±2px); место под переменный текст — `min-height` (B12).
8. Всё, что помещается, видно: ≤ 24 вариантов на широком экране (16 на узком), ≤ 7 шагов мастера, фильтры одним рядом, ничего поверх полей.

10. После `done` глазами: снимки 2560×945, 1920×945 и 390 (и каждая палитра проекта: `shot.mjs --palette grey`), Tab по порядку, фокус виден, Esc закрывает.

## Цикл — всегда один и тот же

1. **Где мы:** `python3 kit/tools/cosmos.py status`. Кита нет → `python3 ~/.cosmos-kit/src/tools/cosmos.py init`
   (в пустой папке — новый сайт; `init --app` — новое приложение; в папке с кодом — применение к проекту).
2. **Что строим — за минуту:** какая страница/экран, для кого, одно главное действие. Тексты — из проекта
   (README, существующий интерфейс, код); чего нет — правдоподобно придумай. Не спрашивай. Язык интерфейса — язык
   просьбы пользователя (или тот, на котором уже сделан проект), один на всех страницах: меню, кнопки, подвал.
3. **Выбери блоки** по таблице `kit/blocks/INDEX.md` и открой только нужные файлы блоков.
4. **Собери:** вставь блоки, замени каждое `ЗАМЕНИТЬ`, удали комментарии-шапки блоков. Своё оформление — только
   в `site.css` (в приложении — в его стилях) и только на токенах кита.
5. **Проверь:** `python3 kit/tools/check.py` → исправь каждую строку `✗` (подсказка после `→`). В Claude Code это
   делает хук после каждой записи файла — ошибки придут сами, исправляй сразу.
6. **Сдай:** `python3 kit/tools/cosmos.py done` → `OK` → открой по каждой странице три снимка: `<страница>-2560-full.png`
   (вся страница), `<страница>-1920.png` и `<страница>-390.png` (телефон); увидел кривое — исправь и снова `done`.
   `done` после OK печатает, что проверить глазами (состояния, клавиатура, тексты) — пройди и только потом отчёт по формату ниже.

## Что сказали → что делать

| просьба | действие |
|---|---|
| сайт / лендинг / визитка (папка пустая) | `init` → `index.html`: topbar, hero, 3–5 блоков, footer; внутренние — копии `page.html` |
| приложение / кабинет / «сразу с UI» | `init --app` → `index.html` из app-shell + list / table / form / empty |
| «примени UI» к готовому проекту | `init` в корне проекта → `references/apply.md` (пошагово) |
| новая страница / экран / раздел | блоки по INDEX → вставить → check |
| компонент (кнопка, поле, диалог…) | класс кита: `check.py --classes <слово>`; разметка — из блока |

## Жёсткие правила (линтер ловит их кодом; список — `check.py --rules`)

- **P1** только тёмная тема: `<html lang="ru" data-theme="dark">`. **P2** стили: fonts → tokens → components → свои.
- **P3** один `<h1>` на страницу. **P4** кит запущен: `bootSite()` (главная), `bootSite({ page: 'inner' })`, `bootSite({ page: 'app' })`.
- **H1** одна `.btn.primary` на секцию/диалог и на экран; в шапке и подвале — никогда.
- **H2** одно `.lit`-слово на страницу, только в заголовке. **H3** красная кнопка — только внутри диалога подтверждения.
- **H4** только существующие классы (кит или свой `site.css`); **H6** иконки только из `kit/icons/sprite.svg`.
- **S1–S4** цвет, шрифт, длительность — только токены `var(--…)`; свои `@keyframes` нельзя. **S6** без inline-стилей.
- **S10** в одном правиле `color` и `background` на одном токене — текст исчезает: на заливке `--ink` текст `var(--bg)`.
- **J1** без `alert/confirm/prompt` — диалог кита и тосты. **K1** файлы кита не правятся.
- **A1** у картинки `alt`, у кнопки-иконки `aria-label`, у поля — подпись над ним.
- **H11** `.empty` — только пустое состояние; **H12** селект в ряду фильтров — `.in.auto`; **S9** `outline: none` — только с `:focus-within` контейнера.
- **T1–T3** тексты: без клише (seamless, «бесшовный», «мощный»), без заголовков-вопросов и «Не X, а Y» — число, факт, результат.
- **H10** страница — либо сайт (`.topbar`), либо приложение (`.app` + `.rail`), не оба.
- Браузер (**B1–B12**, `done`): нет ошибок консоли и 404, нет горизонтальной прокрутки на 2560, 1920 и 390, одна главная кнопка на экране,
  таблицы и списки не пустые (или `.empty`), после «примени UI» не пропали записи и текст (B10); **B11** любой текст ≥ 3:1 с фоном,
  в том числе после нажатия переключателя или шага; **B12** переключатель (`.switch`, `.pills`, шаг) не сдвигает соседей (±2px).

Перед сдачей — `references/lessons.md`: грабли классов, пороги, тексты «плохо → хорошо», клавиатура. Один список для любой модели.

Глазами (линтер не видит; `done` напомнит после OK):
- Заголовок — утверждение («Сайт за вечер»), не ярлык («Возможности»). Кикер — 1–3 слова. Кнопка называет результат («Создать плейлист»).
- Главная — 5–7 секций. В группе выбора всё видно сразу (≤ 24 на широком экране, ≤ 16 на узком); в мастере ≤ 7 шагов; фильтры — одним рядом.
- Приложение: чат — блок `chat` отдельным экраном во всю высоту; советы — блок `advice` строками; одно действие ведёт до результата;
  пустые панели не показывать до первого результата; у внешнего источника — «что-то не так» (`dialog-report`); отметка снимается повторным нажатием.
- Первый запуск — блок `setup` (≤ 7 шагов-карточек, одно действие в ряду, всё откладываемое); умолчание выбора названо в подсказке;
  поле анкеты принимает и запись из базы, и «любую книгу», и «автора целиком» (Alt+Enter) — ввод как думает человек (UX.md §16).
- Снимки: `done` снимает 2560×945, 1920×945 и 390 — открыть все; проект переключает палитры — ещё `shot.mjs --palette grey` (и `paper`).
- Состояния: каждый элемент с состояниями (шаг, чип, строка, кнопка) читается в обычном / сделанном / активном / наведении / фокусе.
- Всё по центру, кроме героя; длинный текст (`.prose`), формы и таблицы — слева внутри центрированной колонки; текст ≤ 640px, чат ≤ 880px.
- Ничего не плавает поверх содержимого и не прыгает при вводе и переключении: место под переменный текст — `min-height`. Подписи — обычный текст 13–14px.
- Клавиатура вручную: Tab по порядку, фокус виден и не перекрыт, Esc закрывает, Enter/Space нажимают; всё, что тянется, делается и кликом.

## Не трать токены

- Не читай `kit/css`, `kit/js`, демо — хук не даст. Классы, токены, иконки: `check.py --classes | --tokens | --icons`; правила — `check.py --rules`.
- Не пиши CSS для того, что уже есть блоком или классом. Не запускай `shot.mjs` после каждой правки — только `done`.
- Не пересказывай файлы и не показывай код в ответе. Отчёт — до 10 строк.

## Отчёт — ровно так

```
Готово: <что сделано одной фразой>
Файлы: <список>
Проверка: cosmos-done OK
Снимки: .cosmos/shots/<…>.png
Допущения: <что решил сам: тексты, разделы, цифры> (или «нет»)
```

## Глубже — сильным моделям и большим задачам

- `references/composition.md` — иерархия, ритм, где уместно излучение; прочитать перед новым типом страницы.
- `references/motion.md` — пружины и сцена; перед любым своим движением (обычно не нужно: всё в `bootSite()`).
- `references/app.md` — сцена и темп в приложении; `references/ux.md` — удобство с порогами (формы, мастер, списки).
- `references/apply.md` — применение к готовому проекту; `references/connect.md` — устройство каркаса.
- `references/lessons.md` — опыт живых проверок и site-research одним чеклистом: грабли, пороги, тексты, сцена, клавиатура.
- Агенты Claude Code: `cosmos-eyes` (слепой тест снимка: понятно ли, что это и что нажать) и `cosmos-critic`
  (разбор снимков по правилам) — для новой главной и новых типов экранов. Их замечания — исправить или обосновать.
- Нового компонента нет в ките — собери в `site.css` на токенах. В сам кит — только отдельной задачей с пунктом в `DESIGN-TODO.md`.
- Осознанное исключение из правила — `<!-- cosmos-ignore: КОД причина -->` на строке (или `"ignore"` в `cosmos.json`)
  и обязательно в отчёт.
