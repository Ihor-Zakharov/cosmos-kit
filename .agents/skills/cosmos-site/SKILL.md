# Сайт в стиле cosmos-kit

## Что это и когда применять

cosmos-kit (`~/projects/cosmos-kit`) — переиспользуемый дизайн-кит: токены, фон-сцена «чёрная
дыра», пружинная физика, каркас страницы (навигация, герой, секции, подвал) и набор компонентов,
обобщённые из проекта «выдра». Применяйте этот навык, когда делаете новый сайт (или раздел
существующего) в том же визуальном языке. Эталон того, как выглядит целый сайт, — `demo/index.html`
кита: шапка, герой с дырой, контентные секции, каталог, подвал. Сначала откройте её и посмотрите.

Это ТОЛЬКО тёмная тема с монохромными поверхностями. Светлая тема отложена (решение пользователя:
в самом конце, см. `DESIGN-TODO.md` §2) — не изобретайте её на ходу, остановитесь и уточните.

## Как подключить кит

1. Скопируйте (не симлинком — сайт должен быть самостоятельным репозиторием) в проект сайта:
   - `src/css/tokens.css`, `src/css/components.css`
   - `src/js/cosmos.js`, `src/js/motion.js`
   - `src/fonts/` (все `.woff2` + `fonts.css`)
   - `src/icons/sprite.svg`
   - `src/scene/plate.webp` (только если используете фон-сцену)
2. В `<head>` — в этом порядке: `fonts.css` → `tokens.css` → `components.css` → свои стили сайта.
3. `<html data-theme="dark">` — тема фиксирована. Ступень излучения — `data-accent` там же (см. ниже).
4. Каркас страницы (всё есть в `components.css`, блоки «Фон-сцена», «Верхняя навигация», «Каркас»):
   ```html
   <div class="cosmos-wrap" id="cosmos-wrap" data-comp="right" aria-hidden="true">
     <canvas class="cosmos" id="cosmos"></canvas>
     <div class="cosmos-fallback"></div>
     <div class="grain"></div>
   </div>
   <header class="topbar" id="topbar">
     <a class="brand" href="/"><svg><use href="icons/sprite.svg#i-mark"/></svg>имя</a>
     <nav class="nav"><a href="#a" aria-current="page">Раздел</a><a href="#b">Раздел</a></nav>
     <div class="topbar-actions"><a class="btn small" href="#">Действие</a>
       <button class="icon-btn menu-btn" aria-label="Меню"><svg><use href="icons/sprite.svg#i-menu"/></svg></button></div>
   </header>
   <div class="site">
     <section class="hero" id="hero"><div class="hero-inner">
       <p class="kicker">кикер</p>
       <h1 class="display">Заголовок с одним <span class="lit">освещённым</span> словом.</h1>
       <p class="lead">Подзаголовок.</p>
       <div class="hero-actions"><a class="btn primary" href="#">Главное</a><a class="btn" href="#">Второе</a></div>
     </div></section>
     <section class="section" id="a"><div class="section-head"><p class="kicker">…</p><h2>…</h2><p>…</p></div>…</section>
     <footer class="site-footer">…</footer>
   </div>
   ```
   и в модуле:
   ```js
   import { createCosmos, attachSceneScroll } from './js/cosmos.js';
   import { attachButtons, attachPointerGlow, attachSwitches, attachChecks, attachDisclosures, attachCards } from './js/motion.js';
   const wrap = document.getElementById('cosmos-wrap');
   const api = createCosmos(document.getElementById('cosmos'),
     { reduced: matchMedia('(prefers-reduced-motion: reduce)').matches });
   if (!api.ok) wrap.classList.add('fallback');
   new ResizeObserver(() => api.resize()).observe(wrap);
   attachSceneScroll(api, { hero: document.getElementById('hero'), wrap });   // живая → за горизонтом
   addEventListener('scroll', () => topbar.classList.toggle('solid', scrollY > 40), { passive: true });
   attachButtons(document);                                   // нажатие/подъём/магнит/фокус для всех кнопок кита
   attachPointerGlow(document, '.glass, .field-body, .btn, .chip-btn, .card');
   attachSwitches(document); attachChecks(document); attachDisclosures(document); attachCards(document);
   // диалоги — только через openDialog()/closeDialog(), тосты — pushToast(), числа — countTo()/odometer()
   ```
   Эталон подключения — `demo/demo.js` (`boot()`), живые образцы каждой анимации с параметрами — `demo/motion.html`.
   Внутренние страницы (не главная): `<div class="cosmos-wrap asleep">` и `api.pause()` сразу после
   создания — сцена размыта и погашена с первого кадра, без анимации появления.
5. Композиция дыры — `data-comp` на `.cosmos-wrap`: `right` (текст слева, дыра справа — по умолчанию),
   `center` (одна фраза по центру над дырой; герою класс `.hero.axis`), `far` (маленькая дыра, короткий
   герой `.hero.short`). Другое положение — свои `--bh-x/--bh-y/--bh-r` на обёртке при `--bh-anchor: custom`.
   На телефоне все композиции сами становятся «текст сверху, дыра снизу».

## Какие токены и компоненты брать

- **Цвет.** Только `--el-a`/`--el-b` (излучение) несут цвет. Все поверхности (`--s1`…`--s4`, `--ink*`,
  `--line*`) монохромны — не нарушайте это точечной подкраской карточек/фонов.
- **Акценты — ось температуры.** `data-accent="violet|ice|white|gold|ember"` на `<html>`; по умолчанию
  белое. Один сайт — одна ступень (бренд), либо ступень как состояние (лёд — покой, белое — норма,
  золото — внимание, угли — горячо), либо как раздел (не больше четырёх равноправных). На одном экране
  не больше двух ступеней, одна из них — белая. При смене ступени перекрашивайте и сцену:
  `api.setAccent(getComputedStyle(document.documentElement).getPropertyValue('--el-a').trim())`.
  Новую ступень или другой цвет не добавляйте — сначала пункт в `DESIGN-TODO.md`.
- **Компоненты** — из `components.css` по классам: `.btn`/`.chip-btn`/`.icon-btn`, `.field`,
  `.tabs`/`.pills` + `.tab-ink`/`.pill-ink`, `.switch`, `.card` (+ `.card.static` для контента),
  `.tree-nav`/`.tnode`, `.crumbs`, `.tag`/`.chip`, `.pager`, `.meter`, `dialog`/`.drawer`/`.modal`,
  `.toasts`, `.ctx`, `.empty`/`.skel`; каркас: `.topbar`/`.island`, `.hero`, `.section`, `.site-footer`,
  `.kicker`, `.display`, `.lead`, `.grid-3`, `.prose`. Разметка — в `demo/index.html`.
- **Не изобретайте новые классы поверх существующих имён.** Нет нужного компонента — соберите из
  токенов или спроектируйте явно и добавьте в кит отдельным проходом с пунктом в `DESIGN-TODO.md`.

## Композиция и тон

Правила вкуса, которые агент соблюдает, собирая новый сайт. Это не рекомендации, а ограничения языка;
если сайт «требует» их нарушить — это повод для нового пункта в `DESIGN-TODO.md`, а не для исключения.

### Иерархия

- **Всё по центру, кроме героя.** Головы секций (`.section-head`), колонки текста, сетки, подвал — центрированы
  по умолчанию; герой — единственное, что стоит на левом датуме (композиция «ось» центрирует и его). Исключения,
  где содержимое остаётся левым **внутри центрированной колонки** (`.centered`): длинный текст статьи (`.prose`),
  таблицы, формы с подписями, дерево/крошки/списки файлов — всё, что читается слева направо построчно. Голова секции
  слева (`.section-head.left`) — только по острой необходимости: рядом с сайдбаром или в приложении с постоянной
  боковой панелью.
- **Один датум.** Левая линия `--datum` задаёт поля; бренд в шапке и герой стоят на ней, остальное центрируется
  в тех же полях.
- **Три уровня чернил, не больше.** `--ink` — заголовки и главное; `--ink-2` — текст; `--ink-3` — кикеры,
  подписи, мета. Четвёртого уровня нет: если что-то «ещё тише», его не должно быть на экране.
- **Роли шрифтов жёсткие.** Geologica — только заголовки (`.display`, `h2`, `.card-title`); Onest — весь
  текст и кнопки; JetBrains Mono — кикеры, числа, метки, код; Unbounded — только имя бренда. Заголовок
  не бывает в Onest, абзац — в Geologica.
- **Одна дыра, один заголовок, одно раскалённое действие.** На экране один `.display`/`h1`, одна
  `.btn.primary` (или `.go-btn`). Второе действие — обычная плита. Кнопка в навигации — плита, не primary.
- **Один индикатор активного состояния на элемент.** Активный пункт показывает либо плашка (`.tab-ink`/`.pill-ink`/
  `.tree-ink`), либо полоска излучения (`.nav-ink` в «линии»), либо цвет — никогда два сразу. Где есть плашка,
  подчёркивания нет.
- **Красная плита — только для необратимого.** `.btn.solid.danger` (и `.chip-btn.solid`) ставится только внутри
  подтверждения разрушительного действия, которое нельзя отменить (удалить навсегда, стереть историю), и никогда
  в общем ряду кнопок. Само действие в интерфейсе — обычная `.btn` с честным текстом («Удалить проект…»);
  опасность передают текст и шаг подтверждения, а не цвет.
- **Заголовки — утверждения.** Кикер моно называет раздел одним-двумя словами, заголовок говорит фразой
  («Одна ось — температура»), абзац объясняет. Заголовок из существительного («Возможности») — слабо.

### Ритм

- **Секции — 96px сверху и снизу** (телефон 64), соседние секции делят один отступ (`.section + .section`).
  Внутри секции шкала 8 / 16 / 24 / 40: кикер→заголовок 12, заголовок→абзац 12, голова→содержимое 40.
- **Герой — весь первый экран** (`100svh`), контент по вертикали в середине; композиция «далеко» — 64svh.
  Ниже героя сразу контент, не второй герой.
- **Одна ширина текста.** Заголовок и абзац секции — до 640px; `.lead` — 560; `.prose` — 640. Сетки
  (`.grid-3`, каталог) — на всю ширину контейнера. Текст на всю ширину 1440 — ошибка.
- **Плиты не вкладываются глубже двух уровней**: плита (`.card`) → вложенный глиф/чип. Карточка в карточке
  в панели — нет.
- **Подвал тихий.** Волосяная линия сверху, бренд с одной строкой, колонки ссылок `--ink-2`, нижняя строка
  моно `--ink-3`. Никаких плит, кнопок и излучения в подвале.

### Где излучение уместно, где нет

- **Уместно** (и только там): кайма и глиф поля ввода; фокус; заливка прогресса и `live-dot`; плашка
  `selected`/`drop-target`; включённый `.switch`; полоска активного пункта навигации (1px); одно
  «освещённое» слово заголовка `.display .lit`; свечение `.btn.primary` (белое); оттенок тумана сцены.
- **Неуместно:** фоны и плиты любого размера; текст длиннее одного слова; иконки в навигации и в списках;
  разделители (они — `--line-*`, белые с прозрачностью); подвал; декоративные градиенты; тени
  (тени — только глубина, без цвета). «Разукрасить, чтобы оживить» — не приём этого языка.
- **Семантические цвета** (`--ok`, `--warn`, `--err`) — только в тостах, опасных кнопках и статусах, никогда
  как акцент или украшение.
- **Плиты над сценой** (`.glass`, `.tabs`, `.island`, `.topbar.solid`) — `--plate` с волосяной рамкой;
  «стекла» с сильным блюром и бликами нет. Блюр подложки — только у `.topbar.solid`, `.island` и `dialog::backdrop`.

### Движение

Основа (была и остаётся): четыре длительности для CSS-переходов, пружины для всего, что следует за пальцем или
курсором, ничего не зациклено без смысла, `prefers-reduced-motion` уважается всеми слоями. Проход «движение»
её не заменил, а достроил: словарь пружин по ситуациям, «капля» для переключателей, такт для событий, переходы
диалогов. Живой эталон каждого правила с параметрами — `demo/motion.html`; параметры в коде — рядом с функциями
в `motion.js`.

**Четыре длительности CSS, других нет** (не менялись): `--t-fast` 180ms — цвет/рамка/свет при наведении;
`--t-base` 320 — раскрытие тела (`grid-template-rows`), подложка диалога, галочка; `--t-slow` 600 — плита шапки;
`--t-scene` 900 — всё, что делает сцена. Кривая — `--ease-out`; `--ease-io` — только для симметричных переходов.
CSS-переходами ходят только цвет, opacity и то, что нельзя сделать transform-ом; всё остальное — пружины.

**Пружины: что и как.** Параметры `response` (период, с; меньше — резче) и `damping` (доля критического
демпфирования; 1 — без отскока). Словарь ситуаций:

| Ситуация | Что двигается | response · damping | Где |
|---|---|---|---|
| Нажатие, вниз | scale .97 (иконки .90, крупные плиты .985) | .09 · 1 — мгновенно, без отскока | `attachButtons` |
| Отпускание | scale → 1 (или → подъём) | .36 · .68 — один лёгкий перелёт | `attachButtons` |
| Отмена (увод пальца) | scale → 1 | .36 · 1 — без перелёта: ничего не «сработало» | `attachButtons` |
| Подъём при наведении | scale 1.02 (иконки 1.06), только мышь | .34 · .72 | `attachButtons` |
| Магнит (только `[data-magnetic]`) | x/y к курсору, 18 % смещения, ≤ 6px | .40 · .80; возврат .50 · .62 | `attachButtons` |
| Фокус с клавиатуры | scale 1.06 → 1 | .45 · .60 | `attachButtons` |
| «Капля»: плашка сегментов/вкладок/дерева/навигации | две кромки: ведущая и ведомая | .26 · .84 и .42 · .80 | `moveInk` |
| «Капля»: ползунок switch | sx 1.45 → 1 по ходу, x к цели | .36 · .66 | `attachSwitches` |

| Появление (тост, модалка, строки) | y 14–20 → 0, scale .96 → 1, blur → 0, o → 1 | .48–.60 · .78–.90 | `enter`, `openDialog`, `pushToast` |
| Уход | тем же путём, короче | .24–.30 · 1 | `exit`, `closeDialog`, `dismissToast` |
| Шторка | x 40 (телефон: y 48) | .50 · .82 | `openDialog` |
| Раскрытие | шеврон r 0 → 90°, содержимое y −8 → 0 | .42 · .60; .50 · .80 | `attachDisclosures` |
| Карточка | наклон ±4° к курсору, scale 1.015; только мышь | .35 · .80; уход .50 · .70 | `attachCards` |
| Число-счётчик | одна пружина на значение | 1.2 · 1 — без перелёта, долгий выбег | `countTo` |
| Барабан цифр | колонка на translateY, по разряду +.03 | .55 · .78 | `odometer` |
| Пульс «в такт» | кольцо scale .6 → 2.4, o → 0; ядро 1.18 → 1 | .9 · 1; .5 · .55 | `kosmos.js: pulse` |
| Состояние кнопки | подпись o 0/y −6/s .92; спиннер→галочка s .8 → 1 | .30 · 1; .40 · .72 (галочка .60) | `buttonState` |
| Сцена: параллакс | указатель, ленивое сглаживание | τ 0.6 с | `cosmos.js` |

Правила поверх словаря:

- **Пружина — для всего, что следует за пальцем/курсором или переключает состояние**: нажатие, плашки, ползунки,
  наклон, магнит, числа, появление/уход. При смене цели пружина сохраняет скорость — цепочки быстрых кликов не рвутся.
- **Только transform и opacity** для пружин (blur — лишь в появлении/уходе). Единственное исключение — ширина/высота
  плашки-«капли» (`--w`/`--h`) и `grid-template-rows` раскрытия: маленький элемент без потомков, один за раз.
- **Отпускание с перелётом, отмена — без.** Перелёт говорит «сработало»; увод пальца или Esc — возврат без отскока.
- **Один индикатор на элемент** (см. «Иерархия») — плашка едет, подчёркивание не дублирует.
- **Смена состояния без скачка ширины**: кнопка в `busy`/`done` держит подпись в потоке и запирает `min-width`;
  надпись не меняют на другую, пока не вернулись в `idle`.
- **Главное действие не двигается за курсором.** `.btn.primary` и `.go-btn` стоят на месте: к раскалённой кнопке
  идут, а не она к курсору. Магнит — только явный `data-magnetic` на второстепенной крупной плите, и то редко.
- **Наведение и магнит — только мышь** (`hover: hover` и `pointer: fine`); на сенсоре остаются нажатие и капля.
  Свет курсора по поверхности (`--mx/--my`) — тоже только с мышью.
- **Пульс «в такт» — для событий, не для декора.** Кольцо расходится от точки, где что-то произошло (пришло
  сообщение, старт загрузки, удар метронома); повторять по таймеру без смысла нельзя. `cosmosApi.pulse('go'|'done')`
  — то же для сцены.
- **Появление один раз** — при загрузке и при добавлении элемента (`enter`, stagger 32–70ms, не больше 8 со сдвигом).
  Без scroll-reveal секций: страница статична, движется сцена и то, к чему прикоснулись.
- **Зациклено только то, что сообщает «идёт процесс»:** сцена, кайма поля (24s, в фокусе 12s), дыхание `live-dot`/
  `.meter.breathing` (2.4s), бегущий сегмент `.meter.indet`, спиннер `.btn-spin`/`.busy`, вращение `.glyph.spin`
  (14s, как медленный механизм). Без процесса — ничего не крутится.
- **Диалоги закрываются после ухода плиты**, не до; `dialog.close()` напрямую — только при `reduced`.
- **`prefers-reduced-motion`**: пружины снапают (`Spring.set` → snap), появления мгновенные, магнит/наклон/подъём
  выключены, сцена стоит, барабан и счётчик ставят значение сразу, галочка нарисована. Проверяйте с включённой опцией.

## Правила

- Тёмная тема — чёрная дыра. Светлая — не сейчас (см. выше).
- Монохромные поверхности, цвет только в излучении.
- Одно «раскалённое» действие на экран.
- `prefers-reduced-motion: reduce` не отключать.
- Русские комментарии в коде кита — сохраняйте стиль при добавлении своего кода рядом.
