# DESIGN-TODO

Пункты, которые требуют дизайнерского решения (вкус, новая композиция, новый цвет) — этот проход
их сознательно не принимал, только выносил и обобщал существующее. Следующий дизайнерский проход
должен явно решить каждый пункт, а не унаследовать значение по умолчанию молча.

1. **Акцентные пресеты (`data-accent`).** В «выдре» это были цвета платформ (YouTube красный/оранжевый,
   TikTok бирюзово-розовый, Instagram розово-оранжевый, «прочее» зелёно-синий). В `tokens.css` они
   перенесены как есть под нейтральными именами `a`/`b`/`c`/`d` — исключительно чтобы показать
   механизм («излучение красится, поверхности — нет»). Для нового сайта нужно решить: сколько
   акцентов нужно, по какой оси они делятся (раздел? статус? бренд?), и какие это цвета.

2. **Светлая тема.** В «выдре» полностью отключена (`data-theme="light"` есть в CSS, но не в работе,
   не проверялась визуально ни разу). Перенесена в `tokens.css` как заготовка. Нужно решить: вообще
   ли делать светлую тему для нового сайта, и если да — переосмыслить «отпечаток/чертёж» с нуля,
   не просто доверять старым значениям.

3. **Навигация верхнего уровня.** `.topbar`, вкладки экранов с «островом» прогресса, подвал —
   не вынесены (см. README «Что не удалось вынести»). Новому сайту нужна своя структура навигации;
   кит даёт только строительные блоки (кнопки, вкладки/пилюли как механизм, иконки), не готовый шаблон.

4. **Карточки данных (задачи, превью, плитки файлов).** Не обобщались — слишком предметно-специфичны.
   Если новому сайту нужны похожие карточки (медиа + прогресс + бейдж + метаданные), их надо
   спроектировать заново из примитивов кита (`.card`, `.meter`, `.chip`, `.tag`), а не пытаться
   стереть из них видео-загрузчик.

5. **Иконки.** Спрайт содержит только общий UI-набор. Бренд/логотип нового сайта, любые предметные
   глифы (не универсальные "папка"/"поиск"/"корзина") — рисуются заново.

6. **Фон-сцена вне первого экрана.** В «выдре» сцена гаснет и расфокусируется на «внутренних»
   экранах (`filter: blur(24px) brightness(.16)` на `.cosmos-wrap` при `data-screen != home`).
   Правило не перенесено как общий компонент — это решение про конкретную многоэкранную структуру
   выдры. Для сайта с другой структурой (одна страница? параллакс-скролл? несколько независимых
   страниц?) поведение сцены на скролле/переходах нужно спроектировать заново.

7. **Мера производительности сцены.** `cosmos.js` содержит эвристику "три подряд долгих кадра →
   выключить пыль и ближний план" (`_lite`) и ограничение разрешения холста. Пороги подобраны под
   железо и нагрузку конкретного продукта — стоит перепроверить на целевых устройствах нового сайта,
   а не считать их универсальными.

8. **Иллюстрация дальнего плана (`scene/plate.webp`).** Текстура специфична (силуэт/пятно света,
   подобранное под композицию «выдры»: центр дыры в 70%/54% кадра, эталонный вид 09:37). Новый сайт,
   скорее всего, захочет свою композицию (положение дыры, форма подсвеченного плана) — это тоже
   дизайнерская работа, не техническая.
